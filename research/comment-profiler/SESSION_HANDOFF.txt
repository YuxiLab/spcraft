## Goal and agreed design
One maintained C++ example workload, comment-directed build generation, separate normal and profiling libraries, and generated benchmark/profile executables. Normal examples run once. Generated executables warm up and repeat only an owning value-returning operation; setup and reference checks remain outside.
Caliper records nested phases and benchmark repetition separately from algorithm iteration. For each phase: sum calls within each rank/repetition, take that repetition’s rank maximum, then compute median, mean, min, max, and sample standard deviation. Overall time comes from the explicit outer call, never the sum of phase maxima.
The project is also intended as a standalone systems/tooling paper with several workloads. Do not claim novelty, low overhead, or scaling from the current smoke results.

## Known limits
The harness currently supports owning value-returning blocks with reusable logical inputs and MPI_COMM_WORLD collective execution. It does not reset arbitrary mutated inputs, support void blocks or arbitrary subcommunicators, bound trace memory, or handle asynchronous accelerator completion. Only the final returned result is checked. Timing-only binaries still record outer Caliper events outside the raw call timer, which can influence state between repetitions. Remote profiling remains deferred at the user’s request.
